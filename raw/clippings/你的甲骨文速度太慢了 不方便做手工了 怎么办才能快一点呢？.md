ok 没问题。那么怎么才能让我的朋友在甲骨文的帮助下快乐的做手工呢？

# 1.hy2协议暴力发包

顾名思义啦 hy2是基于UDP的暴力发包 这个包丢了不慌再发一个  
当然UDP容易被歧视喵 运营商可能会阻断喵  
在这个基础上可以做端口跳跃 这样的话可以部分减轻阻断

# 2.ipv6食用更佳哦

也是很有意思 如果家里有ipv6的话 ipv6的链接可能比ipv4要稳定也能快一点 当然因人而异哦  
另外ipv6的端口跳跃可能比ipv4要好

# 3.套cf

这个老生常谈了喵 使用优选域名就能拿到比较大的带宽啦 ps:我才不会告诉你openai.com是我目前用的最好的优选域名哦

# 4.套壳春川

这个我详细讲一下 众所周知春川相对网络比较快乐 不过只能跨区开哦  
简单来说就是在春川开一条小鸡 然后你链接小鸡 春川区域的小鸡和你主区域的小鸡链接是走甲骨文内网的哦 基本是优质路线不拥堵哦  
但是跨区开小鸡要收我磁盘费 讨厌厌 有没有更好的办法？我不想做手工还花钱  
有的兄弟有的。  
我们都知道pay as go的免费额度是4c 24g arm和2c 2g amd 对吧 emm  
其实还有其他的免费额度哦比如网络负载均衡器nlb。Oracle 的一个云服务。本职工作

它的设计用途是分流量：你有 3 台服务器跑同一个网站，在前面放一个 NLB，用户都访问 NLB 的 IP，NLB 按规则把请求分给后面 3 台，某台挂了就自动跳过。

但我们用的是它的副作用——它本质上是个四层转发器。

四层是什么意思

网络分层，简单说：

- 七层（L7）：懂 HTTP，能看懂"你在请求哪个网页"、能改 header、能解 TLS。OCI 里叫 Load Balancer（LB）。
- 四层（L4）：只认 IP + 端口 + TCP/UDP，不看里面装的是什么，收到包原样转走。OCI 里叫 Network Load Balancer（NLB）。  
	用 NLB 而不是 LB，两个原因：
1. Hysteria2 走 UDP，LB 只支持 TCP/HTTP，不支持 UDP
2. 加密流量不能被中间人拆开，L7 会尝试解 TLS，直接把协议搞坏  
	（当然你也可以用vless的tls试试哦 我不知道LB能不能用vless）

NLB 对它转发的内容一无所知——不知道那是 Hysteria2、不知道是 QUIC、甚至不知道是加密的。它只看到"UDP 包，目标端口 443，转给 10.0.0.70"，照做。

在这套里它干了什么

```markdown
你  ──UDP包──>  （春川 NLB）
                        ↓ 原样转发
                  Oracle 骨干网
                        ↓
                  那台 ARM
```

Oracle 骨干网的好处是不堵车 少丢包  
NLB 本身不是服务器，没有操作系统，不跑任何程序，也不消耗 CPU 内存。 它是 Oracle 网络层面的一个虚拟设备，只能配"监听哪个端口、转给谁"。
